# 번역 작업자 지침 (틀)

팝업 항목이 많아 15개 언어를 번역 작업자(Agent)에게 한 언어씩 나눠 맡길 때 쓰는 지침의 틀이다.
작업 폴더(예: `storage/app/popup-work/` — git 에 들어가지 않는다)에 `en.json`·`ko.json` 을 두고, 아래를 채워 `brief.md` 로 저장한 뒤
작업자마다 "언어: {코드}. `…/brief.md` 를 먼저 읽고 그대로 일하라"고 부른다(15명을 한 메시지로 나란히 — 동시 작업자 한도 20).
2026-09-28 쉘 화면 106개 항목을 이 틀로 번역했다 — 한 언어에 10~16분, 작업자마다 23만~33만 토큰이 들었다.
2026-10-15 사이트 전체(AI·GIT·파이썬·앱 개발·게임 개발·쉘·가이드·자격증)의 빠진 용어 111개와 기존 항목의 언어별 별칭(`existing`)을 맡겼다 — 한 언어에 11~19분, 16만~23만 토큰.
같은 날 쉘 심화 학습(주제 46·예제 174)과 새 항목 10개를 한 작업자에게 함께 맡겼다 — 한 언어에 5~10분, 16만~22만 토큰.
사전 항목이 아니라 **본문 번역 그룹 하나**(예: 쉘 심화 학습 `lang/*/shell_advanced.php`)를 함께 맡길 때는 작업 파일을 그 그룹의 모양 그대로(`{단원: [{desc, snippets: [{code, comment}]}]}`) 두고
`$POPUP/scripts/sonub/translate/verify-group.php` 로 검사하게 한다. 본문 낱말이 그 언어의 사전 표기와 같아야 팝업이 붙으므로 `$POPUP/scripts/sonub/translate/vocab.php {언어}` 목록을 보고 옮기게 한다.
json → PHP 파일은 오케스트레이터가 만든다(작업자는 lang/ 을 고치지 않는다).

작업자 프롬프트에 **반드시** 넣을 것(AGENTS.md "서브에이전트에게 일을 맡길 때"):
- AGENTS.md 와 SONUB-SSOT.md 를 먼저 읽고 그 규정을 따를 것
- 작업 폴더의 자기 언어 파일만 만들 것 — lang/·app/·resources/·tests/ 와 그 밖의 파일은 절대 고치지 않을 것, git 으로 아무것도 바꾸지 않을 것
- 끝나면 검사가 "정상"일 때까지 고치고 결과를 한국어로 짧게 보고할 것

```markdown
# {화면} 용어 팝업 번역 지침 (작업자용)

저장소: /Users/thruthesky/apps/sonub (Laravel, docker compose 앱 컨테이너의 /app).
SONUB 은 왕초보에게 AI·코딩을 가르치는 사이트다. {화면 주소} 화면의 용어·명령·메뉴에 마우스를 올리면 설명 팝업이 뜬다.
팝업 내용은 영어 원문 `{작업 폴더}/en.json` 과 한국어 `ko.json` 에 있다({N}개 항목 + 분류 이름 {K}개).
당신은 이것을 **한 언어로** 번역해 `{작업 폴더}/{언어}.json` 을 만든다.

## 🛑 먼저 지킬 것
- AGENTS.md 와 SONUB-SSOT.md 를 먼저 읽고 그 규정을 따른다(SSOT 10절 다국어, 23절 리엔 — AI 강사 이름은 리엔/Lyen).
  당신은 `{작업 폴더}/` 아래 당신 언어의 파일만 만든다. 다른 파일은 절대 고치지 않는다. git 으로 아무것도 바꾸지 않는다.
- 다른 언어 작업자가 동시에 같은 폴더에서 일한다. 당신 언어 코드가 붙은 파일만 만든다. 임시 파일은 폴더 밖(scratchpad)에 둔다.

## 무엇을 만드나
en.json 과 똑같은 구조: `{"keys": {…}, "terms": {id: {term, short, long, easy, example, aliases(선택)}}, "existing": {이미 있는 id: "별칭 전체 값"}(선택)}`.
id 와 항목마다의 필드는 en 과 똑같이 둔다(aliases 만 선택). `existing` 은 이미 사전에 있는 항목인데 당신 언어의 본문이 표기와 다른 모양으로 써서
팝업이 안 붙는 것 — 값은 `lang/{언어}/glossary.php` 의 `<id 밑줄>_aliases` 기존 값에 이어 붙인 **전체 값**이다. 큰 파일은 조각으로 나눠 쓴다 —
`{언어}.part1.json`({조각 1의 범위}), `{언어}.part2.json`(…), `{언어}.part3.json`(…). 다 쓰면 합치고 검사한다:
    python3 $POPUP/scripts/sonub/translate/merge-parts.py {작업 폴더} {언어}
    bash $POPUP/scripts/sonub/run.sh translate/verify.php {작업 폴더} {언어}

## 번역 규칙
1. 말투는 `lang/{언어}/glossary.php` 의 기존 항목(token_long, terminal_long, port_easy 등)과 같게. ko.json 은 뜻 확인용.
2. 왕초보가 한 번 읽고 이해하게 — 뜻을 자연스럽게 옮긴다. 비유(easy)가 그 문화에서 어색하면 같은 역할의 일상 비유 하나로 바꾼다.
   인공지능을 사람처럼 말하지 않는다. 이모지를 쓰지 않는다.
3. 표기(term)
   - 명령·코드 이름 항목: en 과 똑같이.
   - 개념 항목: **그 언어의 화면 번역(`lang/{언어}/{그룹}.php`)이 실제로 쓰는 낱말**. 팝업은 본문에서 이 표기를 찾아 붙는다. 원어는 괄호로 함께(괄호 앞부분도 본문 표기로 잡힌다).
   - **흔한 낱말이면 표기를 구로 두고 뜻이 분명한 모양만 별칭으로** — 그 낱말이 다른 뜻(예: '흔한', '표', '선행 조건')으로도 본문에 나오면 팝업이 엉뚱한 곳에 붙는다.
   - 메뉴·카드 항목: 그 화면 이름과 글자 하나까지 같게({이름을 가져올 번역 키}).
4. 별칭(aliases, 선택) — 본문이 표기와 다른 모양으로도 쓰면 그 모양을 쉼표로. 본문에 실제로 나오는 모양만. 매칭 규칙:
   - 라틴 문자(es·pt·fr·de·id·vi·tr): 앞뒤에 글자가 붙으면 안 잡힌다 — 복수형·굴절형은 별칭. 튀르키예어 대문자 İ 는 i 와 같게 취급되지 않는다.
   - 러시아어·아랍어·우르두어: 표기 전체가 맞은 뒤 뒤에 붙은 어미는 함께 잡힌다 — 어간이 바뀌는 격변화·앞에 붙는 관사(ال)는 별칭.
   - 일본어·중국어·태국어·힌디어·벵골어: 낱말 경계를 보지 않는다 — 표기가 다른 낱말 속에 들어 있어도 잡힌다(한 글자 표기 금지).
   - 힌디어·벵골어는 교재와 같은 정규화(누크타·য় 분해형)를 쓴다 — 다르면 안 잡힌다.
   - 명령·메뉴 항목에는 별칭을 넣지 않는다.
5. 예시(example) — `\n` 으로 줄을 나눈다. en 과 줄 수가 같다. 줄 맨 앞의 `` `코드` `` 는 **en 과 한 글자도 다르지 않게**(따옴표 속 영어도 그대로) 두고 뒤의 설명만 번역한다.
   코드를 손으로 옮기지 말고 en.json 에서 기계적으로 복사하는 것이 안전하다.
6. 본문 속 기술 표기(-l, $HOME, package.json, Ctrl+C, 명령 이름, 파일 이름)는 번역하지 않는다.
7. JSON — 문자열 안의 `"` 는 `\"`, 역슬래시는 `\\`. 쓰고 나면 `python3 -c "import json; json.load(open('파일'))"`.
8. 분류 이름 keys 도 번역한다.

## 끝나면
검사가 `{언어}: 정상 ({N}개)` 을 낼 때까지 고친 뒤 한두 줄로 보고한다 — 만든 파일, 검사 결과, 표기를 고르며 애매했던 것.
```

모이면(오케스트레이터):

1. `translate/verify.php` 로 16개 언어를 한 번 더 검사하고, HTML 엔티티(`&gt;` 등)가 섞이지 않았는지 `grep` 한다.
2. `translate/combine.py`(작업 파일의 `existing` 은 add-terms 입력의 `aliases` 로 묶인다) → `add-terms.php --dry-run` → `add-terms.php` → `popup-check.php`.
   `aliases` 값이 기존 별칭을 빠뜨리면 add-terms 가 멈춘다 — 작업자가 일부러 뺀 것(그 별칭이 새 항목의 표기를 가로챈 경우)이면 그 별칭만 따로 확인한 뒤 `--overwrite` 를 쓰지 말고 입력에서 그 언어 값을 고쳐 넣거나 번역 파일을 손으로 고친다.
3. **오탐 점검** — `popup-counts.php` 로 언어마다 잡힘 횟수를 비교하고, 한 언어에서만 유난히 많은 용어와 작업자가 보고한 애매한 표기는 `popup-context.php` 로 문맥을 본다. 흔한 낱말이 다른 뜻에 잡히면 그 언어의 표기를 구로 바꾸고 뜻이 분명한 모양만 별칭으로 둔다(번역 파일을 직접 고친다 — 키를 새로 넣으면 알파벳 순서를 지킨다).
4. **정규식 한도** — 표기가 많이 늘면 모든 언어의 매칭 정규식이 컴파일되는지 `GlossaryShellTest` 의 "compiles the matcher…" 가 본다(한도를 넘으면 그 언어의 밑줄이 모두 사라지고 오류가 기록된다).
