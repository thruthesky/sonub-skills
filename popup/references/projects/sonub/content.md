## 핵심 개념

- **상세하되 층으로 나눈다.** 사용자는 "아주 상세하게"와 "가독성 있게"를 함께 원한다 — 한 덩어리의 긴 글이 아니라 한 줄 뜻 → 설명 → 쉽게 말하면 → 예시 → 관련 용어 → 더 배우기로 쌓아, 필요한 만큼만 내려 읽게 한다. 더 깊은 내용은 `href` 의 화면이 맡는다.
- 팝업은 **막힌 순간에** 읽힌다. 학습자는 본문을 읽다 멈췄고, 몇 초 안에 이해하고 본문으로 돌아가고 싶다. 그래서 위에서부터 **한 줄 뜻 → 설명 → 비유 → 예시** 순서로, 어디서 읽기를 멈춰도 그때까지 읽은 것만으로 쓸모가 있게 쓴다.
- 설명은 사전 한 곳(`lang/{언어}/glossary.php`)에만 있다. 같은 용어는 모든 화면·메뉴·리엔의 음성 설명이 같은 문장을 근거로 쓴다.
- 팝업 문장은 **눈으로 읽는 글**이다. 귀로 듣는 말은 스피커가 DeepSeek 로 따로 만든다(voice.md) — 그래서 여기서는 발화를 걱정해 문장을 비틀지 않는다. 다만 이 문장이 DeepSeek 의 근거가 되므로 **사실이 정확해야** 한다.

## 필드

번역 키는 `glossary.<id>_<필드>` — id 의 하이픈은 밑줄로 바꾼다(`api-key` → `api_key_short`).

| 필드 | 필수 | 팝업 자리 | 쓰는 법 | 길이(대략) |
| --- | --- | --- | --- | --- |
| `term` | ✅ | 머리의 표기(강조색) | 그 언어에서 실제로 쓰는 말. 원어를 함께 보이려면 괄호로(`명령줄(CLI)`·`التوكن (Token)`) — 괄호 앞부분도 본문 표기로 잡힌다 | 낱말 하나 |
| `short` | ✅ | 머리 아래 굵은 한 줄, 단추의 `title` | **명사구**, 마침표 없음. 목록·말풍선에서 한눈에 다른 용어와 구별되게 | ko 25자 · en 60자 |
| `long` | ✅ | 본문 | 두세 문장(필요하면 네 문장). ① 무엇인가 ② 왜 중요한가·어디서 만나는가 ③ (있으면) 흔한 오해 하나 | ko 250자 · en 420자 |
| `easy` | 선택 | "쉽게 말하면" 색 상자 | 일상 비유 **한 문장**. `long` 이 이미 비유를 쓰면 넣지 않는다(겹치면 산만하다) | ko 60자 · en 110자 |
| `example` | 선택 | "예시" 상자 | 구체적 예. **가능하면 넣는다**(사용자 지침). 한 줄에 하나(`\n`), 줄 맨 앞에 코드가 있으면 `` `코드` 설명`` — 팝업이 코드(고정폭·왼쪽부터)와 설명을 따로 그린다. **코드는 17개 언어에서 한 글자도 다르지 않게** 두고 설명만 번역한다(`popup-check`·`add-terms` 가 잡는다). 명령은 3~5줄로 자주 쓰는 옵션을, 개념은 1~3줄. 억지로 만든 예는 뺀다 | 줄마다 ko 40자 · en 70자 |
| `aliases` | 선택(언어별) | — | 그 언어의 본문이 표기와 다른 모양으로도 쓸 때 그 모양들을 쉼표로(`표준 입력, 표준 출력`). 라틴 문자 언어의 복수형·굴절형처럼 경계 규칙에 걸리는 모양, 한국어 '셸'·'쉘' 같은 이표기. **본문에 실제로 나오는 모양만.** 명령·메뉴 안내에는 쓰지 않는다 | — |

- 선택 필드(`easy`·`example`)는 **어느 한 언어에 넣으면 17개 언어 모두에** 넣는다(`popup-check.php` 가 잡는다). `aliases` 만 언어마다 있어도 없어도 된다.
- 예시 줄의 코드 안에 백틱(`` ` ``)을 쓰지 않는다 — 줄 맨 앞 코드의 끝으로 읽힌다(명령 치환은 `$( )` 로).
- 이 표의 길이는 기존 50개 항목(예: `token_long` ko 약 170자)에서 잡은 기준이다. 넘으면 팝업이 스크롤된다 — 더 쓸 것이 있으면 `long` 을 늘리기보다 `easy`·`example`·`related` 로 나눈다.

## 사전 항목(TERMS)

`app/Content/Glossary.php` 의 `TERMS` 에 한 줄을 더한다. 번역보다 먼저 정한다(id 가 번역 키가 된다).

```php
'sampling' => ['category' => 'ai', 'aliases' => ['sampling'], 'related' => ['temperature', 'token', 'inference'], 'href' => '/ai/build'],
```

| 값 | 규칙 |
| --- | --- |
| id | 소문자·숫자·하이픈. 영어 기준의 짧은 낱말(`context-window`). **한 번 정하면 바꾸지 않는다** — 번역 키·`data-term`·`:exclude` 가 가리킨다 |
| `category` | `CATEGORIES`(ai·data·dev·web·infra) 중 하나. 새 분류를 만들면 `CATEGORIES` 와 번역 `glossary.cat_<분류>` 17개 언어를 함께 더한다 |
| `aliases` | **언어와 무관한** 표기만 — 약어(`LLM`), 영문 원어(`fine tuning`), 흔한 한글 이표기(`기계 학습`). 그 언어의 대표 표기는 `term` 이 준다. 두 글자 이하 라틴 약어는 다른 낱말에 박히기 쉬우니 이득이 뚜렷할 때만(`AI` 는 경계 규칙으로 막고 있다) |
| `related` | 등록된 id 2~3개. 팝업 안 칩으로 갈아탄다. `long` 에 나오는 다른 전문 용어를 우선 넣는다 |
| `href` | 더 배울 화면의 경로(언어 접두사 없이). 그 경로에 화면이 없으면 링크가 저절로 사라진다 |
| `match` | 메뉴 안내(메뉴 링크·단원 카드·화면 사용법)는 `false` — 본문에서 찾지 않고 사전 창에도 없다. **id 는 `menu-` 로 시작**한다(GlossaryTest 가 지킨다) |
| `scope` | 한 화면에서만 뜻이 맞는 낱말(쉘의 '프롬프트'·'경로'·'변수')은 `'scope' => 'shell'` — 그 화면이 `scope="shell"` 로 감쌀 때만 찾고, 같은 표기면 이긴다. 다른 화면의 문장을 엉뚱하게 잡지 않는다 |
| `auto` | 낱말이지만 영어 낱말과 같아 본문에서 찾으면 틀리는 것(명령 `for`·`if`·`set`·`read`·`cut`·`man`)은 `false` — 예제 단추·물음표로만 |
| `case` · `exact` | 명령 이름은 `'case' => true`(대소문자까지 같을 때만 — 'Cat' 은 안 잡는다). 한 항목 안에서 일부 표기만 그렇게 하려면 `exact`('PATH') |
| `source` | 용어집 화면(/glossary)에 보일 용어의 출처 — `['from' => SOURCES 의 키, 'anchor' => 원문 안의 자리, 'docs' => 공식 문서]`. 새 출처면 `SOURCES` 에 한 줄을 먼저 더한다(SSOT 23절 "용어집") |
| `cues` | 이 뜻의 **문맥 신호** — 이 뜻일 때 가까이(같은 문장·문단·화면 주제) 함께 나오는 용어 id 또는 화면 이름. 없으면 `related`. 낱말이 아니라 id 라 17개 언어에 그대로 통한다. 이 뜻에서만 나오는 말을 고른다(Git 브랜치: `git`·`commit`·`repository`). 어디에나 나오는 `model`·`data`·`agent` 는 틀린 뜻을 고르게 한다 |
| `context` | `true` 면 일상어로도 흔한 낱말 — 가까운 문맥에 `cues` 가 있을 때만 감싼다(`branch` — "one branch of it" 은 Git 이 아니다). 근거가 없으면 팝업 없음 |
| `shares` | 다른 용어의 표기를 이 뜻의 후보로 빌린다(`neural-network` 의 `['network']` — 신경망 설명 속 "the network"). 빌린 표기는 늘 근거가 있어야 이긴다 |
| `avoid` | 언어별 정규식 목록(`['en' => ['\\bin\\s+skill\\b']]`) — 표기를 덮으면 그 뜻이 아니다("differ in skill" 은 실력). 다른 언어는 보통 다른 낱말을 쓰므로 그 언어에서만 |
| `links` | 함께 볼 공식 문서가 여럿일 때 `LINKS` 의 키 목록(`['cc-glossary-harness', 'codex-harness']`). 제목·주소는 `LINKS` 에 한 번만 적고(제목은 번역하지 않는다), 팝업·용어 사전 창·용어집 화면이 "공식 문서"(`glossary.links_label`) 목록으로 보인다 |

**같은 표기, 여러 뜻** — 한 언어에서 두 항목이 같은 표기를 가지면 둘 다 후보로 남고 문맥이 고른다(SSOT 23절 "용어 문맥 뜻", `Glossary::resolve()`). 화면 전용 낱말(scope)이 모든 화면의 낱말보다 먼저인 것은 그대로고, 같은 층이면 `cues` 점수(같은 문장 4 · 같은 문단 1 · 화면 주제 2, 페이지 앞 글은 9점까지 동점 가르기), 같으면 등록 순서다. 그래서 같은 표기의 두 항목은 **모두 `cues` 를 갖고 서로 달라야 한다** — `popup-check.php` 가 아니면 문제로 낸다.

새 낱말을 넣을 때 **"이 표기가 사이트 어디선가 다른 뜻으로 쓰이나?"** 를 먼저 묻는다 — `popup-index.php query en <표기>` 로 모든 문장을 본다. 다른 뜻도 전문 용어면 따로 항목을 만들어 각자 `cues` 를 주고(`grok` 모델 계열 · `grok-cli` 코딩 에이전트), 다른 뜻이 일상어면 항목을 만들지 않고 `context` 로 둔다. 몇몇 영어 구절이 그래도 틀리게 고르면 `cues` 를 늘리지 말고 `avoid` 에 그 구절을 넣는다.

## 문체 원칙

1. **모르는 사람 기준** — 설명 안에 또 다른 전문 용어를 쓰지 않는다. 꼭 써야 하면 그 말도 사전에 있어야 하고 `related` 로 잇는다.
2. **무엇 → 왜/어디서** 순서. 정의만 있고 "그래서 왜 알아야 하나"가 없으면 초보자는 다시 본문에서 막힌다.
3. **비유는 하나**, 사실을 비틀지 않는다. 비유가 틀리게 이끄는 부분이 크면 한 구절로 밝힌다("다만 ~는 아닙니다").
4. **인공지능을 사람처럼 말하지 않는다** — "생각한다·안다·겪는다" 대신 "계산한다·고른다·만든다". 환각(hallucination)은 그럴듯하지만 틀리거나 근거 없는 출력을 가리키는 기술 용어다(리엔 지침 `App\Llm\Prompts::LYEN` 과 같은 기준).
5. **확인된 사실만** — 숫자·연도·제품 이름은 확인한 것만 쓰고, 가상 수치는 예시라고 밝힌다.
6. **짧은 문장** — 한 문장에 한 가지. 쉼표로 네 가지를 잇지 않는다.
7. **본문과 같은 이름** — 메뉴·화면 이름을 가리킬 때는 그 언어에 이미 있는 번역과 똑같이 쓴다(AGENTS.md "다국어 번역").

## 항목 종류별 쓰는 법

| 종류 | 무엇을 설명하나 | `term` | `short` | `long` |
| --- | --- | --- | --- | --- |
| 용어·단어 | 낱말의 뜻 | 그 낱말 | 뜻을 명사구로 | 무엇 → 왜/어디서 → 오해 하나 |
| 개념 | 여러 문장에 걸친 생각(예: "다음 단어 확률") | 개념 이름 | 핵심 한 줄 | 개념이 어떻게 돌아가는지 두세 단계 |
| 문장 | 화면의 어려운 문장 하나 | 그 문장의 짧은 제목("이 문장의 뜻") | 한 줄 요약 | "쉽게 말해 ~라는 뜻입니다" + 왜 여기서 중요한가. 문장을 그대로 되풀이하지 않는다 |
| 명령 | 쉘 명령 하나의 사용법 | 명령 이름 그대로(`ls`) — 17개 언어 같음 | 무엇을 하나(동사구) | 무엇을 하나 → 자주 쓰는 옵션 → 조심할 점. 예시는 `` `ls -la` 숨김 파일까지 `` 같은 줄 3~5개 |
| 메뉴 | 메뉴 항목·카드가 여는 화면 | 메뉴 이름·카드 제목과 글자 하나까지 같게(쉘 단원 = `shell.{단원}.title`) | 그 화면에서 하는 일 | 무엇을 배우나 → 이 화면을 어떻게 쓰나. 예시는 그 화면에서 연습할 명령 |
| 화면 사용법 | 화면의 한 부분(예제 단추·실습 터미널·미션·진도) | 그 부분의 화면 이름과 같게 | 그 부분이 하는 일 | 어떻게 쓰나(누르면 무엇이 되나) → 막혔을 때. 예시는 코드 없는 단계 줄도 된다 |

- 문장·개념·메뉴 항목의 id 는 뜻이 드러나게: `concept-next-word-probability`, `sentence-ai-build-counts`, `menu-python`.
- 문장 항목은 그 문장이 바뀌면 함께 고친다 — 번역 키 옆 주석 대신, 사전 항목의 `href` 에 그 화면 경로를 넣어 어디 문장인지 남긴다.

## 언어별

- **말투는 그 언어의 기존 `glossary.php` 를 따른다** — ko 는 합니다체("다룹니다"), ja 는 です・ます, 그 밖도 같은 파일의 기존 항목을 두세 개 읽고 맞춘다(AGENTS.md: 예 — 독일어는 du).
- 표기는 그 언어 사용자가 실제로 쓰는 말이다(ja `トークン`, zh `词元`처럼 이미 파일에 있는 말을 먼저 찾는다). 새 말을 지어내지 않는다.
- 문장부호는 그 언어의 것(ja `。`, hi `।`, ar `،`·`؟`). 작은따옴표는 `\'` 또는 `’`(AGENTS.md).
- 자리표시자(`:count` 등)는 번역하지 않는다 — 팝업 문장에는 보통 쓰지 않는다.
- 오른쪽→왼쪽 언어(ar·ur)도 같은 문장 구조로 쓰면 된다 — 방향은 CSS 가 논리 속성으로 푼다.
- en 을 먼저 쓰고, 나머지 16개 언어는 **en 이 아니라 뜻을** 옮긴다. 비유가 그 문화에서 어색하면 같은 역할의 다른 비유를 쓴다(비유는 하나라는 규칙은 같다).

## 넣는 절차

1. `TERMS` 에 항목을 넣는다(위 표).
2. 17개 언어를 모은다. 두 가지 방법이 있다.
   - **항목이 몇 개일 때** — JSON 하나에 id → 언어 → 필드로 직접 쓴다(`add-terms.php` 입력 형식, 위 예시).
   - **항목이 많을 때**(쉘 106개처럼) — 작업 폴더(예: `storage/app/popup-work/`, git 에 안 들어간다)에 언어마다 파일 하나(`{언어}.json` = `{"keys": {키: 값}, "terms": {id: {필드}}}`)로 쓴다. en·ko 는 직접 쓰고, 나머지 15개 언어는 번역 작업자(Agent)에게 한 언어씩 나란히 맡긴다 — 지침은 [translate-brief.md](translate-brief.md) 의 틀을 채워 쓴다. 작업자는 `$POPUP/scripts/sonub/translate/merge-parts.py`(조각 합치기)·`$POPUP/scripts/sonub/translate/verify.php`(en 과 항목·필드·예시 코드 대조)로 스스로 검사한다. 모이면 `$POPUP/scripts/sonub/translate/combine.py` 가 17개를 add-terms 입력 하나(`input.json`)로 묶는다.
   - **이미 있는 항목에 그 언어만의 표기를 더할 때**(본문이 표기와 다른 모양으로 써서 팝업이 안 붙는 것 — 쉘 1단원 목표의 "[대상]" 처럼) — 입력의 `"aliases": {id: {언어: "별칭 전체 값"}}`. 언어마다 있어도 없어도 되고, 값은 기존 `<id>_aliases` 를 모두 품어야 한다(더하기만 — 빼려면 `--overwrite`). 번역 작업자의 작업 파일에서는 `existing` 으로 받는다.
3. 검사만 먼저 돌리고, 통과하면 넣는다. 스크립트는 17개 언어·필드·빈 값·자리표시자·예시 코드·기존 값 덮기를 검사하고, 파일마다 원래 모양(들여쓰기·알파벳 순서)을 지켜 쓴다.
   ```bash
   bash $POPUP/scripts/sonub/run.sh add-terms.php /app/storage/app/popup-terms.json --dry-run
   bash $POPUP/scripts/sonub/run.sh add-terms.php /app/storage/app/popup-terms.json
   ```
   입력 JSON 은 컨테이너가 읽는 저장소 안(`storage/app/`)에 두고, 넣은 뒤 지운다. 기존 값을 고쳐야 할 때만 `--overwrite`(요청 없이 기존 번역을 고쳐 쓰지 않는다 — AGENTS.md). 스크립트가 "원래 모양으로 다시 그릴 수 없다"고 멈추면 그 파일은 누가 손으로 고친 것이니 손으로 넣는다.
4. 검사한다.
   ```bash
   bash $POPUP/scripts/sonub/run.sh popup-check.php
   docker compose exec -T app sh -c 'for f in lang/*/glossary.php; do php -l "$f" > /dev/null || echo "문법 오류: $f"; done'
   docker compose exec app php artisan test --filter=Glossary
   ```
   AGENTS.md "다국어 번역"의 키·자리표시자 검사(`G=glossary`)도 돌린다 — `aliases` 는 언어마다 달라서 "빠진 키/남는 키"로 나올 수 있다(정상). 그 밖의 줄이 없어야 한다.
5. 화면을 감싼다(design.md) — 그 화면의 문장에서 새 용어가 잡히는지 `popup-audit.php` 로 언어 두세 개를 다시 본다(표기가 그 언어 본문의 낱말과 맞지 않으면 안 잡힌다).
6. **오탐을 점검한다** — `popup-counts.php <그룹> <범위> <id 앞머리>` 로 언어마다 잡힘 횟수를 비교하고, 한 언어에서만 유난히 많은 용어는 `popup-context.php <그룹> <언어> <범위> <id>` 로 문맥을 본다. 흔한 낱말이 다른 뜻에 잡히면 표기를 구로 바꾸고 뜻이 분명한 모양만 별칭으로 둔다(쉘 작업 때 fr 'tableau'·vi 'biến'·'điều kiện'·bn 'শর্ত'·ur 'حساب' 을 이렇게 고쳤다).

## 태그가 든 번역 문장

`<x-glossary.text>` 는 평문만 받아 `<strong>`·`<br>` 도 글자로 보인다. `popup-audit.php` 가 `[태그 있음]` 으로 표시한 문장은:

1. 감싸지 않는다(가장 흔한 답 — 그 문장의 용어는 다른 문장에서 잡히면 충분하다), 또는
2. 비LMS 화면이면 태그를 Blade 로 옮기고 번역을 태그 없는 키 여러 개로 나눈다 — 17개 언어 모두 나눠야 한다, 또는
3. 그 구절만 `<x-glossary.term id="…">` 로 명시한다(design.md).
