# sonub-skills — навыки для агентов (Agent Skills) от SONUB

[README](README.md) · [English](README.en.md) · [한국어](README.ko.md) · [中文](README.zh.md) · [日本語](README.ja.md) · [Español](README.es.md) · [Português](README.pt.md) · [Français](README.fr.md) · [Deutsch](README.de.md) · **Русский** · [Tiếng Việt](README.vi.md) · [Bahasa Indonesia](README.id.md) · [ไทย](README.th.md) · [Türkçe](README.tr.md) · [हिन्दी](README.hi.md) · [বাংলা](README.bn.md) · [العربية](README.ar.md) · [اردو](README.ur.md)

Этот репозиторий — **маркетплейс навыков**. Каждый навык — это стандартный [Agent Skill](https://agentskills.io) (папка с файлом `SKILL.md`), поэтому он работает в Claude Code, Codex, Gemini CLI, GitHub Copilot CLI и в любом другом агенте, который читает Agent Skills. В Claude Code его также можно установить как плагин из этого маркетплейса (`sonub-skills`), и тогда обновление выполняется одной командой.

| Навык | Что делает |
|------|------|
| [`gp`](skills/gp) | Управляйте всей своей работой в **GitHub Projects** с помощью git и `gh` CLI |
| [`claude-skill`](skills/claude-skill) | **Изучайте Claude Code и пользуйтесь им лучше** — 14 уроков с тестами, ответы, сверенные с официальной документацией, проверка настроек (doctor), сводка всех новых функций из CHANGELOG и `/claude-skill update`, чтобы подтягивать новые (имя плагина `cc-skill`) |
| [`popup`](skills/popup) | **Объясняйте термины всплывающими подсказками при наведении** на страницах и в документации любого проекта — значение, простыми словами, примеры, исходный код, связанные термины и ссылки «узнать больше» на ваши собственные страницы, из одного JSON-глоссария |

## Установка — глобально (для пользователя) или для проекта

Все навыки устанавливаются одинаково. Вместо `<плагин>` подставьте имя плагина из таблицы (`gp`, `cc-skill`, `popup`).

**Шаг 1 — добавьте маркетплейс (один раз на компьютере)**

```bash
claude plugin marketplace add thruthesky/sonub-skills
```

**Шаг 2 — установите туда, где он нужен**

| Область | Команда | Кому и где доступен | Где записывается |
|------|------|------|------|
| **Глобально (пользователь)** — по умолчанию | `claude plugin install <плагин>@sonub-skills` | вам, во всех проектах на этом компьютере | `~/.claude/settings.json` |
| **Проект (общий для команды)** | в папке проекта: `claude plugin install <плагин>@sonub-skills --scope project` | всем, кто работает в этом репозитории | `.claude/settings.json` (закоммитьте его) |
| **Локально (только вы, только этот проект)** | в папке проекта: `claude plugin install <плагин>@sonub-skills --scope local` | вам, только в этом репозитории | `.claude/settings.local.json` |

- В чате команда `/plugin install <плагин>@sonub-skills` открывает экран, где можно выбрать область. Если вы устанавливали из терминала, выполните `/reload-plugins` в открытом чате.
- Проверить: `claude plugin list` (показывает область). Обновить: `claude plugin marketplace update sonub-skills && claude plugin update <плагин>@sonub-skills`. Удалить: `claude plugin uninstall <плагин>@sonub-skills`.
- Если один и тот же плагин задан в нескольких областях, локальная важнее проектной, а проектная важнее глобальной.

**Пусть коллеги получают его автоматически** — закоммитьте это в `.claude/settings.json` репозитория. Когда коллега подтвердит доверие к папке (trust), Claude Code сам добавит маркетплейс и установит плагины.

```json
{
  "extraKnownMarketplaces": {
    "sonub-skills": { "source": { "source": "github", "repo": "thruthesky/sonub-skills" } }
  },
  "enabledPlugins": { "gp@sonub-skills": true, "cc-skill@sonub-skills": true, "popup@sonub-skills": true }
}
```

**Без плагинов — скопируйте папку** в папку навыков вашего агента (`<навык>` = `gp`, `claude-skill` или `popup`).

| Инструмент | Глобально (пользователь) | Проект |
|------|------|------|
| Claude Code | `~/.claude/skills/<навык>` | `<проект>/.claude/skills/<навык>` |
| Codex · Gemini CLI · GitHub Copilot CLI | `~/.agents/skills/<навык>` | `<проект>/.agents/skills/<навык>` |

```bash
S=claude-skill; DIR=~/.claude/skills      # только этот проект: DIR=.claude/skills
mkdir -p "$DIR" && rm -rf "$DIR/$S" && curl -fsSL https://codeload.github.com/thruthesky/sonub-skills/tar.gz/refs/heads/main | tar -xz -C "$DIR" --strip-components=2 "sonub-skills-main/skills/$S"
```

**Проще всего** — скажите агенту *«установи плагин cc-skill из thruthesky/sonub-skills глобально»* (или *«только для этого проекта»*), и он сам выполнит команды выше.

## gp — вся ваша работа на доске GitHub Project

Вы говорите со своим ИИ-агентом обычными словами — *«создай issue: на iPhone кнопка входа ничего не делает, приложи этот скриншот»*, *«перенеси в Done»*, *«добавь колонку Review»*, *«что у меня в работе?»* — а агент выполняет это на вашей доске GitHub Project через `gh` и затем перечитывает результат, чтобы подтвердить.

### Что охватывает

- **Объяснение GitHub Projects** — репозиторий, issue, проект (доска), элемент (item), черновик (draft), поле, Status = колонки, представление (view), workflow. Агент может объяснить всё это на вашем языке.
- **Аккаунт и вход** — шаги регистрации нового аккаунта GitHub, установка `gh`, `gh auth login`, права (scopes) `project` и `repo`.
- **Доски** — создать, переименовать, добавить описание, сделать публичной/приватной, закрыть/открыть снова, удалить, привязать репозитории, показать список своих досок, выбрать доску по умолчанию.
- **Колонки (канбан)** — добавить, переименовать (карточки остаются на месте), изменить порядок, задать цвет, удалить (сначала перенесите карточки в другую колонку).
- **Поля и представления** — пользовательские поля (текст, число, дата, одиночный выбор), представления «доска», «таблица» и «дорожная карта» с фильтрами.
- **Issues** — создать (сразу в нужную колонку, с метками, вехой (milestone), родительским issue, пользовательскими полями), изменить, перенести между колонками, закрыть (переходит в Done), открыть снова, прокомментировать, убрать с доски, архивировать, удалить.
- **Изображения** — прикрепить скриншоты или видео к тексту issue или к комментарию.
- **TODO** — чек-лист `- [ ]` внутри issue: добавить, отметить, снять отметку, удалить; прогресс виден в списках. Черновики (draft) для быстрых идей, которые потом можно превратить в issues.
- **Люди** — назначить и снять исполнителя, посмотреть, кто чем занят, пригласить соавторов в репозиторий и выдать роли на доске.

### Что нужно

- Аккаунт GitHub (бесплатный). Ещё нет аккаунта? Зарегистрируйтесь на https://github.com/signup — код из письма, головоломка, тариф Free (около трёх минут).
- [`gh`](https://cli.github.com) — GitHub CLI (macOS `brew install gh`, Windows `winget install GitHub.cli`), вход выполнен с правами `project` и `repo`.
- Python 3.8 или новее (только стандартная библиотека).

   claude plugin install gp@sonub-skills

   - Если он уже установлен, вместо этого выполни: claude plugin update gp@sonub-skills
2. Любой другой агент: помести его в папку навыков DIR — для всех проектов: ~/.agents/skills, только для этого проекта: <проект>/.agents/skills.

4. Кратко сообщи мне, что установлено, каков результат doctor и что теперь я могу говорить, например, «покажи мои проекты GitHub».

**Claude Code — две строки в терминале** (работает в любой версии):

#### Глобальная и локальная (для проекта) установка

| | Глобально — все проекты | Локально — только этот проект |
|------|------|------|
| Плагин Claude Code | `claude plugin install gp@sonub-skills` | в папке проекта: `claude plugin install gp@sonub-skills --scope project` (записывается в `.claude/settings.json` и общий для всей команды · только для вас: `--scope local`) |
| Копия папки для Claude Code | `~/.claude/skills/gp` | `.claude/skills/gp` |
| Codex · Gemini CLI · Copilot CLI | `~/.agents/skills/gp` | `.agents/skills/gp` |
| Используемая доска | `/gp init <URL доски> --global` → `~/.config/gp/config.json` | `/gp init <URL доски>` → `<проект>/.gp.json` |

Где установлен навык и какую доску он использует, выбирается отдельно. Обычно навык устанавливают глобально один раз, а каждому проекту задают его доску через `/gp init <URL доски>`.

### Первый запуск

Попросите агента *«настрой gp»* (Claude Code: `/gp:gp`, Codex: `$gp`). Он выполнит:

```bash
python3 scripts/gp.py doctor                    # gh ✓ · вход ✓ · права ✓ · доска по умолчанию
gh auth login                                   # только если вход не выполнен — введите одноразовый код в браузере
gh auth refresh -s project,repo                 # только если не хватает прав
python3 scripts/gp.py projects                  # ваши доски
python3 scripts/gp.py init <URL доски>          # доска этого проекта (.gp.json) · для всех проектов: --global … или создайте новую:
python3 scripts/gp.py project-create --title "Моя работа" --columns "Todo,In Progress,Review,Done" --repo you/your-repo --use
python3 scripts/gp.py view-add Board --layout board
```

### Выбор доски — `/gp init`

У каждого проекта разработки может быть своя доска GitHub Project. Дайте агенту адрес доски в папке проекта — и работа этого проекта будет вестись на этой доске.

```text
/gp init https://github.com/users/thruthesky/projects/17/views/1
```

Если навык установлен как плагин Claude Code: `/gp:gp init …`; в Codex: `$gp init …`. Можно сказать и так: «используй https://… как доску этого проекта».

- **Локально (по умолчанию)** — внутри git-репозитория настройка сохраняется в `<корень репозитория>/.gp.json` и используется только в этом проекте (и его подпапках). Секретов в файле нет: закоммитьте его, чтобы команда работала с той же доской, или добавьте в `.gitignore`, чтобы оставить только себе.
- **Глобально** — `/gp init <URL> --global` (или «сделай её доской по умолчанию для всех проектов») → `~/.config/gp/config.json`, используется в любой папке без `.gp.json`.
- Подходит любая страница доски (`/views/2`, доски пользователя `/users/…`, доски организации `/orgs/…`). Перед сохранением проверяется, что доска существует и доступна для чтения.
- `/gp init` без аргументов показывает текущую доску и её файл настроек. Удалить: `gp.py init --unset` (глобально: `--unset --global`).
- `/gp init` также записывает указание в `AGENTS.md`/`CLAUDE.md` этого проекта и в глобальные `~/.claude/CLAUDE.md`/`~/.codex/AGENTS.md`: «создавать, изменять, удалять, перечислять и искать issue, задачи и TODO в GitHub Project всегда через навык gp». С URL добавляется «работать на этой доске» с этим URL. Повторный запуск обновляет только эту часть; `--show` только показывает, `--no-instructions` пропускает указание, `--remove-instructions` удаляет его.
- Какая доска используется: `--owner/--number` → `GP_OWNER`/`GP_PROJECT` → `.gp.json` проекта → глобальная настройка.

### Как пользоваться — просто скажите

| Вы говорите | Агент выполняет |
|------|------|
| «Создай issue: на iPhone кнопка входа ничего не делает. Шаги: воспроизвести, исправить, протестировать. Приложи shot.png» | `create --repo app --title "…" --todo воспроизвести --todo исправить --todo протестировать --image shot.png` → колонка Todo |
| «/gp init https://github.com/orgs/my-team/projects/3» | `init …` → сохраняется как доска этого проекта (`.gp.json`) |
| «Возьми в работу» · «Перенеси #12 в Review» | `move app#12 doing` · `move app#12 review` |
| «Готово!» | `close app#12` — закрывает issue и переносит его в Done |
| «Добавь в его TODO „обновить документацию“» · «отметь первый пункт» | `todo app#12 add "обновить документацию"` · `todo app#12 done 1` |
| «Добавь колонку Urgent в начало» · «Переименуй Review в QA» | `column-add Urgent --first --color red` · `column-rename Review QA` |
| «Передай это alice» · «Пригласи bob в репозиторий» | `assign app#12 alice` · `invite bob --repo app` (сначала спрашивает) |
| «Что у меня в работе?» | `list --assignee @me --state open`, затем предлагает одну следующую задачу |
| «Запиши идею на доску: тёмная тема» | `create --draft --title "тёмная тема"` |
| «Добавь поле Priority» | `field-add Priority --type single_select --options "High,Medium,Low"` |

Все команды: [skills/gp/references/commands.md](skills/gp/references/commands.md) · `python3 scripts/gp.py -h`.

### Как это работает

- **Только `gh` и стандартная библиотека Python.** gh вызывается со списком аргументов (без оболочки), а заголовки и тексты передаются через stdin — кавычки, эмодзи и переводы строк никогда не ломаются.
- **ID по имени.** ID полей, колонок и вариантов ищутся при каждом запуске, поэтому колонки можно переименовывать на сайте, ничего не ломая. При переименовании колонки её карточки остаются на месте.
- **Каждое изменение перечитывается.** После изменения скрипт выводит строку `check:` с реальным состоянием на GitHub (состояние, колонка, исполнители, метки). Агент отчитывается по ней.
- **Изображения** загружаются через `--attach` в gh (GitHub user-attachments). Со старой версией gh изображения коммитятся в ветку `gp-assets` репозитория issue, и на них ставится ссылка.
- **Безопасно по умолчанию.** У каждой изменяющей команды есть `--dry-run`. Удаление issue, доски, поля или колонки с карточками требует `--yes`, а навык велит агенту сначала спросить вас. Перед приглашениями (они отправляют письмо реальному человеку) агент тоже сначала спрашивает.
- **Настройка доски** сохраняется для каждого проекта в `.gp.json` (локально) и для всех проектов в `~/.config/gp/config.json` (глобально). `--owner/--number` или `GP_OWNER`/`GP_PROJECT` имеют приоритет над обеими.

Примечание: сразу после создания issue список проекта на GitHub может показать его только через несколько секунд. Строка `check:` читает issue напрямую и всегда актуальна.

### Обновление и удаление

```bash
claude plugin marketplace update sonub-skills && claude plugin update gp@sonub-skills   # Claude Code
claude plugin uninstall gp@sonub-skills
```

Другие агенты: чтобы обновить, снова выполните строку `curl … | tar`; чтобы удалить, удалите папку `gp`.

## claude-skill — изучайте Claude Code и пользуйтесь им лучше

Новая версия Claude Code выходит почти каждый день (их уже больше 400). Этот навык учит Claude Code по порядку, отвечает на вопросы по **актуальной официальной документации**, а не по памяти, проверяет ваши настройки и хранит сводку всех новых функций из CHANGELOG. Одна команда `/claude-skill update` добавляет в навык только что вышедшие функции.

### Что охватывает

- **Курс из 14 уроков** — от установки и первых запросов до цикла «изучить → спланировать → написать код → закоммитить», управления контекстом, CLAUDE.md и памяти, режимов разрешений, контрольных точек (checkpoints), навыков, субагентов, хуков, MCP, плагинов и маркетплейсов, запуска без интерфейса (headless) и GitHub Actions, а также долгой работы без присмотра с проверкой результата. В каждом уроке есть **упражнение в вашем собственном проекте** и контрольные вопросы, а ваш прогресс сохраняется.
- **Разбор Claude Academy** — 64 урока по Claude на [Claude Academy](https://academy.claude.com/all?kind=tutorial&product=chat), а также уроки и курсы по Claude Code (Claude Code 101, Claude Code in action, Agent Skills, Subagents). То, что вы изучаете в чате (Projects, память, коннекторы, навыки, Research, выбор модели и уровня усилий (effort)…), сопоставлено с тем, как это делается в Claude Code.
- **Ответы, сверенные с документацией** — на вопросы вроде «как работают хуки?» или «что такое область (scope) плагина?» навык ищет и читает code.claude.com и отвечает командой, примером и ссылкой на документацию.
- **Все новые функции из CHANGELOG** — все 422 версии [CHANGELOG.md](https://raw.githubusercontent.com/anthropics/claude-code/refs/heads/main/CHANGELOG.md) (v0.2.21 – v2.1.302) без исправлений ошибок, сведённые в 14 тем, плюс 30 функций, которые стоит знать, и последние добавления.
- **`/claude-skill update`** — загружает свежий CHANGELOG, находит версии, которые навык ещё не охватывает, добавляет их функции в заметки, шпаргалку и уроки и записывает, до какой версии всё охвачено.
- **Проверка настроек (doctor)** — смотрит вашу версию, файлы настроек (пользователя, проекта, локальные), длину CLAUDE.md, правила (rules), автопамять, навыки, субагентов, плагины и MCP-серверы и предлагает исправления.
- **Шпаргалка, советы и руководства по созданию** — команды, сочетания клавиш, флаги CLI и расположение файлов на одной странице; привычки, которые работают; как создавать навыки, субагентов, хуки, MCP-серверы, плагины и маркетплейсы.

### Установка

Как в разделе [Установка](#установка--глобально-для-пользователя-или-для-проекта) выше. Плагин называется **`cc-skill`** (Claude Code резервирует имена плагинов, начинающиеся с `claude-`, для собственных плагинов Anthropic). Навык сохраняет имя `claude-skill`, поэтому его вызывают командой `/claude-skill`.

```bash
claude plugin marketplace add thruthesky/sonub-skills
claude plugin install cc-skill@sonub-skills                    # глобально — все проекты
claude plugin install cc-skill@sonub-skills --scope project    # этот проект, общий для команды
```

Нужны Python 3.8+ и доступ в интернет (навык читает официальную документацию и CHANGELOG).

### Как пользоваться

| Вы говорите | Навык делает |
|------|------|
| `/claude-skill` · «давай изучать Claude Code» | Показывает уроки и ваш прогресс, начинает следующий урок |
| `/claude-skill lesson 5` · «следующий урок» | Объясняет урок, выполняет упражнение в вашем проекте, задаёт контрольные вопросы, сохраняет прогресс |
| `/claude-skill quiz` | Пять вопросов по пройденному, по одному, с оценкой |
| «Как с помощью хука запускать prettier после каждого изменения?» | Читает официальную документацию и отвечает примером настройки и ссылкой |
| `/claude-skill new` · «что нового?» | Сначала самые полезные из новых функций, для каждой — как её попробовать |
| `/claude-skill doctor` · «проверь мои настройки» | Проверяет ваши настройки и предлагает исправления (спрашивает, прежде чем что-то менять) |
| `/claude-skill tips` · `cheatsheet` · `academy` | Привычки, которые работают · команды и сочетания клавиш · разбор Academy |
| `/claude-skill build skill` · «сделай мне хук» | Выбирает подходящий механизм и создаёт его вместе с вами в вашем проекте |
| `/claude-skill update` | Обновляет заметки навыка о функциях по свежему CHANGELOG |

Если навык установлен как плагин, работает и `/cc-skill:claude-skill …`. Codex: `$claude-skill …`.

### Как работает `/claude-skill update`

1. `scripts/cc.py update-check` сравнивает версию, до которой доходят заметки (отметка `covered-through` в `references/changelog-features.md`), с последней версией в CHANGELOG.
2. В установленной копии плагина сначала выполняется `claude plugin update cc-skill@sonub-skills`, чтобы получить опубликованные заметки. Чтобы править исходники навыка (git checkout), передайте `--source <папка>`. Без исходников запись идёт в `~/.config/claude-skill/changelog-local.md` — этот файл сохраняется при обновлениях плагина.
3. `cc.py changelog --since <охваченная версия>` выводит пункты новых версий (исправления скрыты); агент добавляет новые функции в их темы, переписывает «Последние добавления», вносит новые команды и сочетания клавиш в шпаргалку и исправляет уроки, которые устарели.
4. `cc.py mark-covered <последняя версия>` переносит отметку; в git checkout он повышает версию и делает коммит (push — только по вашей просьбе).
5. В конце агент сообщает охваченный диапазон версий и 3–7 новых функций, которые стоит попробовать, и как попробовать каждую.

### Инструмент — `scripts/cc.py`

Только стандартная библиотека Python.

```bash
python3 scripts/cc.py doctor                 # проверить настройки Claude Code + советы
python3 scripts/cc.py docs hooks             # поиск по официальной документации (llms.txt)
python3 scripts/cc.py read hooks --section "Hook events"   # прочитать один раздел страницы
python3 scripts/cc.py changelog --count 5    # последние 5 версий (исправления скрыты)
python3 scripts/cc.py changelog --grep worktree --count 400   # найти функцию по названию
python3 scripts/cc.py update-check           # охваченные версии и последняя версия
python3 scripts/cc.py lessons                # уроки и прогресс
```

## popup — объясняйте каждое сложное слово там, где его встречает читатель

Читатель спотыкается об одно незнакомое слово — «токен», «endpoint», «идемпотентный» — и теряет весь абзац. Этот навык вешает на такое слово небольшую карточку: наведите на него курсор (на телефоне — коснитесь, с клавиатуры — переведите фокус), и она объяснит термин по слоям — значение в одну строку, короткое пояснение, сравнение из обычной жизни, строки с примерами, фрагмент исходного кода, связанные термины и **ссылку «узнать больше» на другую страницу вашего же проекта**. Работает в любом проекте: статические сайты, генераторы документации, одностраничные приложения, сайты с серверным рендерингом и обычный Markdown, который читают на GitHub.

### Что охватывает

- **Один глоссарий — одно место** — все объяснения лежат в одном JSON-файле (или по одному на каждый язык); страницы лишь ссылаются на id терминов, поэтому одно и то же слово везде читается одинаково.
- **Готовый набор** — `popup.js` и `popup.css`, без фреймворка и без этапа сборки. Обычный текст внутри `main`/`article` оборачивается автоматически (при первом употреблении на странице); для словосочетаний, предложений, кнопок «?» и ссылок с предпросмотром при наведении есть явная разметка. Одна карточка на странице, закрепление по клику, связанные чипы меняют содержимое на месте, Esc возвращает фокус, нижняя панель (bottom sheet) на телефонах, языки с письмом справа налево, тёмная тема и оформление через CSS-переменные.
- **Умное сопоставление** — сначала самое длинное написание, границы слов для каждого письма (латиница, кириллица, корейские частицы, арабские приставки, CJK), термины, которые действуют только в одном разделе (`scope`), и названия команд с учётом регистра.
- **Правила написания** — как составить карточку, которую новичок поймёт с первого прочтения, на каждом языке, который поставляет проект: зачем нужно каждое поле, длина, одно сравнение, проверенные факты и примеры всякий раз, когда есть настоящие.
- **Инструменты** — `popup.py check` проверяет глоссарий (все локали, одинаковый код примеров во всех языках, связанные id, существование целей «узнать больше», конфликты написаний); `audit` показывает, какие термины документ уже использует, и находит термины-жаргон без записи; `add` безопасно добавляет новые термины; `md` + `link` превращают глоссарий в `GLOSSARY.md` и ставят ссылку на первое употребление в ваших Markdown-файлах, а значение показывают как title при наведении.
- **SONUB** — внутри репозитория SONUB навык опирается на собственный Laravel-глоссарий SONUB (17 языков, голос ИИ-репетитора), а не заводит вторую систему.

### Установка

Как в разделе [Установка](#установка--глобально-для-пользователя-или-для-проекта) выше, с именем плагина **`popup`**.

```bash
claude plugin marketplace add thruthesky/sonub-skills
claude plugin install popup@sonub-skills                    # глобально — все проекты
claude plugin install popup@sonub-skills --scope project    # этот проект, общий для команды
```

Для инструмента нужен Python 3.8+. Набор работает в любом современном браузере.

### Как пользоваться

| Вы говорите | Навык делает |
|------|------|
| `/popup docs/getting-started.md` · «добавь на эту страницу всплывающие подсказки из глоссария» | Находит сложные слова, пишет записи, подключает набор и проверяет всё в браузере |
| `/popup token, sampling, temperature` | Пишет эти три записи и прикрепляет их там, где термины используются |
| «объясни пункты меню при наведении» | Добавляет ссылкам предпросмотр при наведении, а для телефонов и клавиатуры — кнопки «?» |
| «сделай README понятным для новичков» | Собирает `GLOSSARY.md` и ставит ссылку на первое употребление каждого термина, со значением при наведении |
| «переведи глоссарий на японский» | Добавляет `ja` в каждую запись и проверяет, что ничего не пропущено |

Если навык установлен как плагин, работает и `/popup:popup …`. Codex: `$popup …`.

### Инструмент — `scripts/popup.py`

Только стандартная библиотека Python.

```bash
python3 scripts/popup.py init popup --locales en,ko   # копирует popup.js/css, создаёт glossary.json, пишет .popup.json
python3 scripts/popup.py audit docs                   # термины по файлам + жаргон без записи
python3 scripts/popup.py add new-terms.json --dry-run # добавляет новые термины (с проверкой, молча ничего не перезаписывает)
python3 scripts/popup.py check                        # проверяет глоссарий
python3 scripts/popup.py md && python3 scripts/popup.py link README.md docs --write   # Markdown на GitHub
```

Затем добавьте в шаблон страницы два тега:

```html
<link rel="stylesheet" href="/popup/popup.css">
<script defer src="/popup/popup.js" data-glossary="/popup/glossary.json"></script>
```
